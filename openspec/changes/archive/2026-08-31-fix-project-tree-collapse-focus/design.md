## Context

Project mode 文件树同时维护三类相关状态：当前选中项、实际焦点节点和右侧预览目标。当前通过鼠标收起目录时，如果被收起目录包含当前选中文件，文件节点会从可见树中消失，但选中/焦点/预览状态可能仍指向隐藏文件，造成用户看到的焦点位置和预览内容不一致。

本变更只收敛 project mode 文件树的前端状态行为。实现时应先定位现有树组件或 composable/store 中负责展开状态、选中路径、焦点路径和预览路径的代码，再把收起目录后的状态校正抽为统一方法。

## Goals / Non-Goals

**Goals:**
- 保证目录收起后，选中项、焦点项和预览目标始终指向可见节点。
- 在收起当前选中文件所在目录或祖先目录时，把焦点转移到被收起的目录。
- 通过统一方法处理鼠标、键盘或批量折叠入口，避免不同输入路径行为分叉。
- 保持现有展开、文件选择和预览加载机制不变，只在必要时校正目标。

**Non-Goals:**
- 不重构整棵文件树渲染结构。
- 不改变文件系统读写、项目扫描或排序规则。
- 不新增后端接口。
- 不修改数据库结构。
- 不改变非 project mode 的导航或预览行为。

## Decisions

### D1: 抽取收起后的可见性校正方法

**选择**: 在文件树状态层抽取类似 `ensureSelectionVisibleAfterCollapse(collapsedDirPath)` 的统一方法。该方法在目录被收起后判断当前选中路径是否仍可见；如果当前选中路径位于被收起目录内部，则统一切换选中项、焦点项和预览目标到 `collapsedDirPath`。

**原因**: 问题本质是状态不变量失效，不是鼠标事件本身。把校正逻辑放到状态层，可以让鼠标点击、键盘折叠、命令触发折叠和未来可能的批量折叠复用同一规则。

**替代方案**:
- 只在鼠标点击处理器里修正: 可以解决当前复现路径，但键盘或其他折叠入口仍可能出现同类问题。
- 在预览组件里兜底隐藏文件: 会掩盖状态错误，树焦点仍可能停在不可见节点。

### D2: 收起祖先目录时聚焦被点击收起的目录

**选择**: 当当前选中文件位于被收起目录的任意层级子孙内时，校正目标为本次被收起的目录，而不是文件的直接父目录。

**原因**: 用户的操作对象是被点击的目录。收起该目录后，它是被收起子树在可见树中的代表节点，焦点落在这里最符合视觉连续性。

**替代方案**:
- 跳到选中文件的直接父目录: 如果直接父目录也被隐藏，焦点仍不可见。
- 跳到根目录: 过度丢失上下文。

### D3: 预览更新复用现有选择流程

**选择**: 校正时尽量调用现有 `selectNode` / `setSelectedPath` / `updatePreview` 等选择流程，而不是直接分别写多个状态字段。目录预览应沿用现有目录选中时的预览表现。

**原因**: 选中、焦点和预览通常还有 loading、错误态、缓存或 analytics 等附带逻辑。复用现有流程可以降低遗漏副作用的风险。

**替代方案**:
- 直接设置 `selectedPath`、`focusedPath` 和 `previewPath`: 实现短，但容易绕过已有状态同步逻辑。

### D4: 路径包含判断必须使用结构化路径关系

**选择**: 判断 `selectedPath` 是否位于 `collapsedDirPath` 内部时，应使用规范化后的路径段关系或既有路径工具，不使用简单字符串前缀匹配。

**原因**: 简单前缀会把 `src/app` 和 `src/application` 这类兄弟路径误判为父子关系。Windows 路径分隔符和大小写也需要按项目既有路径规范处理。

**替代方案**:
- 使用 `selectedPath.startsWith(collapsedDirPath)`: 实现简单，但边界错误明显。

## Risks / Trade-offs

- [Risk] 现有代码可能没有独立的 `focusedPath`，只有 DOM focus 或 `selectedPath`。-> Mitigation: 实现时保留“可见选中项驱动焦点”的原则，如果没有焦点状态，则在 DOM 更新后把焦点恢复到校正后的目录节点。
- [Risk] 目录预览可能尚未独立实现。-> Mitigation: 如果已有目录选中空态或摘要态，复用该表现；如果没有，至少应清理文件预览并显示当前目录上下文，避免继续展示隐藏文件。
- [Risk] 折叠状态和选择状态更新顺序可能导致短暂闪烁。-> Mitigation: 在同一状态事务或同一个 action 中完成折叠与校正，必要时用框架的 next tick 处理 DOM focus。
- [Risk] 路径规范化不一致可能导致误判。-> Mitigation: 优先复用项目已有路径工具；没有则补一个小范围 helper 并为分隔符、同名前缀、根目录场景加测试。

## Context

切换器先将预选 tab 的状态恢复到共享的 `PreviewEditor`，此时 `activeTabId` 仍指向原 tab；提交时更新 `activeTabId`，又调用 `restoreTabContent`。该函数无条件执行 `deactivateTab`，清空刚恢复的内容。`PreviewEditor` 的加载 effect 只观察预览槽身份和路径，提交前后两者相同，因而不会再加载。随后 `cacheTabState` 将空内容覆盖有效缓存。当前 `originalFileSize` 未随缓存恢复，空内容判断还可能使用上一文件的大小。

项目已有进行中的 `restore-workspace-context-on-switch` 变更。本设计仅调整内容身份、切换提交、缓存有效性及加载提示；实现时应保留该变更已引入的焦点与滚动恢复语义。

## Goals / Non-Goals

**Goals:**

- 切换器预览后确认同一目标时保持已恢复的内容、预览 DOM 和编辑器会话，同时完成正式激活后的收尾工作。
- 不让切换过渡态的空内容污染有效缓存；受损缓存命中后能够重读磁盘内容。
- 保留真正的空文件及用户主动清空的未保存草稿；提示准确反映加载、失败或可编辑状态。

**Non-Goals:**

- 改变 MRU 顺序或切换快捷键语义。
- 重构全部预览器、文件监听器或已有的焦点恢复方案。
- 为已关闭的 tab 持久化缓存；当前缓存只存在于运行中的进程。

## Decisions

### 1. 按显示身份决定是否清理旧内容

以工作区 tab ID、预览槽 ID 和文件路径组成显示身份。`restoreTabContent` 仅在目标身份与 `PreviewEditor` 当前身份不同的情况下先执行 `deactivateTab`；预览后提交同一身份时继续同步 TabState 和布局，并运行提交后的焦点、项目树监听等收尾逻辑，但不再次清空内容。身份包含 tab 和槽 ID，以覆盖两个 tab 打开同一路径的情况。

备选方案是提交时完全跳过 `restoreTabContent`。它容易遗漏预览阶段因 `activeTabId` 尚未更新而被守卫跳过的异步工作，故不采用。另一备选是让 `deactivateTab` 永不清空内容，会重新引入旧内容短暂渲染到新槽的问题，也不采用。

### 2. 用显式加载状态判定缓存有效性

为当前文本内容维护与显示身份绑定的状态：`loading`、`ready`、`error`、`transition`；只有成功读取、有效缓存恢复或用户编辑产生的 `ready` 内容可以写入文本缓存。`deactivateTab` 将状态标为 `transition`，正常切换前的快照已保存，之后即使发生重复保存也不会覆盖有效缓存。成功读取的空文本和用户主动删空的未保存草稿仍为 `ready`，可以保存。

缓存项保存对应文件的大小或等价元数据，并在恢复时更新 `originalFileSize`。缓存命中若缺少有效内容状态，或发现未修改的非空文件对应异常空快照，则丢弃该项并重读；不能用文件修改时间相同作为唯一有效性条件。存在未保存修改时保留草稿，不进行自动磁盘覆盖。读取失败进入 `error`，呈现错误和重试入口，避免空内容被无限解释为“加载中”。

备选方案是仅判断 `content === '' && originalFileSize > 0`。它无法可靠区分真实空文本、主动删空的草稿以及旧文件大小，故不作为唯一依据。

### 3. 将编辑入口与加载状态关联

按 `e` 时：`loading` 显示等待提示；`error` 显示失败及重试；`ready` 按文件类型进入编辑，包括合法空文本。空内容不再单独代表正在加载。

## Risks / Trade-offs

- [身份比较遗漏槽 ID] → 使用已有 `previewSlotKey` 表示工作区与槽身份，并加入路径；测试两个 tab 的相同路径及同 tab 多槽。
- [过渡态阻止保存合法草稿] → 切换前先快照，用户编辑包括删空均保持 `ready`；测试未保存空草稿切换往返。
- [自愈读取覆盖未保存内容] → `isModified` 的草稿优先于磁盘重读，异常缓存只在无未保存修改时自动驱逐。
- [异步收尾回到旧 tab] → 延续现有 generation 和目标身份守卫，并验证快速连续切换。

## Migration Plan

运行时缓存不跨进程保存，无数据迁移。实现后运行定向回归测试与 `npx svelte-check`；若出现回归可回退此变更，用户可通过关闭受影响的 tab 重新读取文件。

## Open Questions

无阻塞问题。实现时需确认当前进行中的工作区上下文恢复代码已合入的具体形态，再将身份判断接入其最终调用路径。

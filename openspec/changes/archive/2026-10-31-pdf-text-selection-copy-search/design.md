## Context

PDFium 已负责文档缓存、页面渲染及全文搜索。三栏预览使用按需挂载的瓦片 Canvas，全屏视图使用单页 Canvas；两者都没有可选择的文字 DOM。搜索结果目前只有矩形坐标，前端切换命中时跳到页首，并且已有结果时按 Enter 不会对修改后的查询词重新搜索。

## Goals / Non-Goals

**Goals:**

- 在两个视图中提供对可提取 PDF 文字的鼠标选择和原生复制。
- 文字层与 Canvas 在页面缩放、平移及滚动时保持对齐。
- 搜索词修改后可重新搜索，并将当前命中滚动或平移到可见区域。
- 文字提取按页按需执行，避免长文档打开时加载全部文字。

**Non-Goals:**

- 扫描件 OCR、PDF 内容编辑、注释或永久高亮。
- 改变现有 PDF 栅格渲染、瓦片调度与搜索后端的基本机制。

## Decisions

### 1. 复用 PDFium 提取字符和位置

增加按页读取文本布局的 Tauri 命令，返回按 PDF 阅读顺序排列的 Unicode 文本单元及其 PDF 坐标和页面索引。保留生成空格、换行所需的信息；无可映射 Unicode 的字符不伪造内容。前端共享类型和请求封装放在 `pdf-shared.ts`，不把整份文档的文字附在 `get_pdf_info` 返回值上。

备选是引入 PDF.js 作为第二套解析器；它会重复加载和解析 PDF，并带来与当前 PDFium 画面坐标不一致的风险。使用现有 PDFium 作为唯一坐标来源更直接。

### 2. 在画面上覆盖可选择的透明文字 DOM

共享文字层构建逻辑把 PDF 坐标换算为页面内 CSS 坐标。文字按阅读顺序进入 DOM，视觉位置由提取的边界框确定，使用透明文字和可见的浏览器选择高亮。三栏预览把文字层挂到 `.pdf-page-wrapper`，全屏视图把 Canvas 和文字层放在同一变换容器中；层的尺寸与页面尺寸同步更新。

采用浏览器原生选择与 `Ctrl+C`，避免自行实现拖选、跨行文本拼接和剪贴板权限。备选是按鼠标坐标命中字符并维护自定义选区；这会增加跨行、跨页、双击选词和复制顺序的复杂度。实施时需验证文字层的真实阅读顺序、字符间距与透明文字命中区域，必要时按行合并文字节点，但不能牺牲选择精度。

### 3. 与页面生命周期及链接层协调

三栏视图只为已挂载页面请求文字布局，按路径和文件版本标识缓存，设置有界上限；页面销毁时移除 DOM，文件变化时丢弃旧布局。缩放时复用 PDF 坐标重新布局，不重复提取文字。进行中的跨页拖选涉及的已挂载页面在鼠标释放前不卸载。链接仍可单击打开，拖动经过链接文字时允许建立文本选区。

### 4. 搜索状态区分“输入词”和“已执行词”

按 Enter 时，若输入词与已执行词不同则执行新搜索；相同时切换当前命中。给异步搜索请求加入序号，旧查询返回时不得覆盖新查询结果。命中定位使用现有结果矩形，在三栏视图滚动到对应页内坐标，在全屏视图平移使矩形进入视口；页面变更后再应用定位。搜索高亮维持与当前结果一致。

## Risks / Trade-offs

- [PDF 字符顺序或边界框异常] → 用中英文、换行、多栏和旋转页面样例检查；仅对可提取文字承诺选择准确性。
- [大量字符 DOM 影响滚动] → 按页延迟加载、限制保留页数，优先按连续文本片段组织节点并复用缩放布局。
- [页面虚拟化中断跨页选择] → 拖选期间固定相关页面，释放后恢复常规淘汰。
- [透明文字层影响链接和键盘导航] → 明确层叠顺序与点击/拖动规则，并验证 `Ctrl+C` 不被全局快捷键拦截。
- [搜索返回顺序与输入变化竞争] → 用查询序号丢弃过期结果，定位以当前查询结果为准。

## Migration Plan

新增命令和文字层可以逐步接入两个视图；现有图像渲染作为文字提取失败时的可见画面。无需数据迁移。若出现兼容问题，可移除文字层入口并继续使用现有 PDF 渲染和搜索命令。

## Open Questions

无阻塞项。具体的文本节点粒度由实施时的 PDFium 返回数据和交互验证决定。

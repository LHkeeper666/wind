## Context

当前图片由 `file-loaders.ts` 获取缩略图或原图字节，`ImagePreviewer` 用 `object-fit: contain` 渲染到预览槽。`PreviewEditor` 将普通 `j/k/h/l` 作为槽滚动处理。PDF 预览已有以指针为锚点的平滑缩放逻辑，但其瓦片渲染解决的是 PDF 页面重新栅格化问题。

## Goals / Non-Goals

**Goals:**
- 保持选中图片的现有快速预览路径和视觉响应。
- 在预览槽中提供完整适配、四向平移和稳定的平滑缩放。
- 用户主动放大超过缩略图有效像素时，异步升级到原图而不阻塞交互。

**Non-Goals:**
- 不新增图片瓦片接口，不修改现有缩略图生成算法。
- 不调整全屏图片查看器的快捷键或切图行为。
- 不改变 PDF、文本和其他预览类型的键盘行为。

## Decisions

### 图片专属视口状态

每个图片预览槽持有图片尺寸、当前倍率、目标倍率、平移位置、是否已手动缩放以及原图请求状态。初始倍率按可用视口与图片宽高计算，保持比例、完整居中；未手动缩放时跟随视口尺寸变化重新适配。保留各槽视图状态，切换槽时不意外重置。

图片专属键盘和滚轮事件只在该预览槽处于活动焦点时生效；由图片处理器消费后阻止通用预览滚动和浏览器页面缩放。`j/k/h/l` 平移且在边界处夹紧。`Ctrl+=/-` 以视口中心为锚点，`Ctrl+滚轮` 以指针位置为锚点。借用 PDF 的缩放增量、目标值与逐帧收敛思路；`prefers-reduced-motion` 下直接跳到目标倍率。倍率和位移始终按图片坐标计算，缩放过程中保持锚点位置。

选择专属视口而非仅扩大 `<img>` 并滚动通用槽，是为了同时保证居中适配、稳定锚点及四向边界处理。缩放使用浏览器已有位图渲染，不采用 PDF 式瓦片。

### 原图升级时机

初次选中沿用当前 `read_image_thumbnail` 路径，即使初始适配尺寸在高 DPI 屏幕上超过缩略图有效像素，也不自动请求原图。只有用户主动放大时，以当前图片在屏幕上的 CSS 尺寸乘 `devicePixelRatio`，与已加载位图的实际像素宽高比较；超过任一轴的有效像素时，发起一次后台原图请求。无缩略图的图片（例如 GIF 和 SVG）不走此升级路径；手动“查看原图”仍可提前发起请求。

请求进行时继续展示缩略图并允许平移缩放。原图解码成功后仅替换位图来源，保留视图坐标、倍率和焦点。请求以槽、文件路径及渲染版本校验；用户快速切换图片或关闭槽后，旧结果不得覆盖新图，旧 Blob URL 必须释放。失败时继续展示缩略图并允许重试。

选择越过阈值后按需升级，而非首次显示即升级，以保护“选中即预览”的性能。重复滚轮事件共用同一请求，不重复读盘。

## Risks / Trade-offs

- [缩略图放大到原图就绪前会暂时模糊] → 保持交互连续，原图完成后无跳动替换。
- [大图原图解码占用内存] → 每槽只保留所需资源，切换和销毁时释放未使用的 URL；不预加载相邻原图。
- [快速切换时异步结果过期] → 使用文件身份与渲染版本检查，丢弃过期结果。
- [高 DPI 下阈值可能较早触发] → 仅由用户主动放大触发，不影响初次选中。

## Migration Plan

无数据迁移。先实现图片专属视口和事件，再接入原图升级；通过图片预览交互与快速切换场景验证。回退时可恢复旧图片渲染和通用槽滚动路径。

## Open Questions

无阻碍实施的待定问题。缩放上限及平移步长可沿用 PDF 预览的交互量级，在实现时据视觉效果微调。

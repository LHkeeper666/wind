## Context

`DirectoryPanel.svelte` 当前从一次 `read_directory` 响应构建单层 `displayFiles` 列表，`h/l` 的含义是切换目录。项目模式仅服务当前目录面板，但必须与普通模式共存；树根在进入时固定，不能随着选中文件或目录改变。现有后端已经提供按目录路径读取条目的命令，前端目录缓存和刷新协调器可复用。

## Goals / Non-Goals

**Goals:**
- 在当前目录面板中提供按需加载、可展开的固定根目录项目树。
- 保留普通模式的全部既有行为，以及左侧父目录面板的行为。
- 让每个 Tab 独立恢复其项目树根、展开路径、光标路径和滚动位置。
- 避免递归读取大项目造成 UI 卡顿或无界并发请求。

**Non-Goals:**
- 不新增后端递归列目录 API，不在进入模式时预扫描完整项目。
- 不支持 FTP 或虚拟根目录作为项目树根；这类路径保持普通模式并给出提示。
- 不改变文件选择、预览、编辑、复制/移动/删除等既有操作语义。
- 不实现 git 状态、文件监听或项目配置识别。

## Decisions

### 在 `DirectoryPanel` 内维护树节点与可见节点扁平列表

每个树节点包含 `FileEntry`、深度、父路径、子项加载状态与展开状态。渲染和 `j/k/gg/G` 基于由树节点派生的可见扁平列表，路径作为稳定标识；普通模式继续使用现有单层 `displayFiles`。这与现有 TOC 的“嵌套数据 + 可见扁平列表”模型一致。

备选方案是在后端一次递归返回完整树。该方案会在大仓库中产生高 I/O、响应和内存成本，且无法自然表达逐步展开，因此不采用。

### 展开时按需读取，递归展开使用受控队列

首次展开目录时调用现有 `read_directory` 并写入 `directoryCache`；后续展开复用已加载内容。`L` 对选中目录递归展开，使用有限并发队列和节点上限；达到上限时停止并提示用户。目录加载失败时在对应节点显示错误且允许重试。

备选方案是 `L` 串行读取，虽简单但大目录树响应过慢；无限并发则可能压垮 Tauri IPC 和文件系统。

### 项目模式键位覆盖仅在中间面板激活时生效

项目模式下：`l` 展开当前折叠目录，若已展开则移动到首个可见子项；`L` 递归展开当前目录；`h` 收起当前展开目录，否则移动到父目录；`H` 每次收起当前树中最深的一层展开目录；`K` 选择当前节点的父目录。文件上的 `l` 与 `Enter` 保持现有激活行为。`Ctrl+Shift+E` 由 `PanelLayout` 在当前目录面板焦点时处理，用于切换项目模式。

备选方案是全局无条件拦截该组合键。该方案会干扰编辑器和终端，故仅允许当前目录面板消费。

### 项目树视图状态写入 `TabState`

新增 `projectMode`、`projectRootPath`、`projectExpandedPaths`、`projectSelectedPath` 与 `projectScrollOffset`。树节点本身不跨 Tab 序列化：恢复时从固定树根读取根节点，再根据保存的展开路径按需重建可见分支。普通模式仍使用原有光标和滚动字段。

备选方案是保存整个树和所有条目，会导致 Tab 状态膨胀且容易缓存过期，因此不采用。

### 刷新保持当前树上下文

普通目录刷新逻辑继续原样运行。项目模式刷新树根和已加载的展开目录；失效目录重新读取，保留仍存在的展开和选中路径，若选中节点不存在则回退到最近可见祖先。文件操作完成后的刷新协调器需要触发项目树对应分支同步。

## Risks / Trade-offs

- [大型或深层项目的递归展开耗时长] → 使用按需加载、有限并发和可提示的节点上限。
- [文件操作或外部修改导致已加载树过期] → 复用目录版本和缓存失效机制，刷新受影响分支并提供手动 `R` 刷新。
- [普通模式与树模式的快捷键冲突] → 明确按模式分发，且仅当前面板可进入项目模式。
- [恢复展开状态会产生多次异步读取] → 按保存路径逐层恢复，并在加载期间保持可交互与取消旧恢复请求。

## Context

虚拟根目录从 `FtpManager::get_configs()` 生成 `[FTP] <name>` 条目。目录面板的 `i` 已打开文件信息，但 FTP 连接条目不适用。配置以名称为键保存在 JSON 中；`ftp://<name>/...` 同时用于导航、标签页和传输任务。后台传输创建独立 FTP 会话。

## Goals / Non-Goals

**Goals:** 在根目录连接条目上按 `i` 编辑现有参数；区分保存与重连；避免在编辑界面暴露已有密码；保持其他条目的 `i` 行为。

**Non-Goals:** 连接重命名、新建/删除站点、FTPS/SFTP、改变现有密码存储格式或 `:ftp disconnect` 的语义。

## Decisions

1. `DirectoryPanel` 仅当当前路径为虚拟根目录、当前选中条目路径精确为 `ftp://<name>/` 且该名称存在于保存配置中时，将 `i` 路由到独立 FTP 编辑弹窗。其他项继续调用现有文件信息流程。弹窗开启时沿用现有模态焦点管理。
2. 新增仅供编辑的配置读取命令，从已保存的配置文件读取名称、主机、端口、用户及是否已有密码，不返回密码，也不等待可能正被网络操作占用的 `FtpManager` 锁。更新命令接收连接名和可编辑字段，密码采用“保留”或“替换”的显式语义，避免空字符串歧义。既有 `list_ftp_connections` 返回类型暂不改变，以免扩大兼容范围；编辑界面不调用它。
3. 后端验证连接存在、主机与用户名非空、端口在 1–65535，并在写盘成功后更新内存配置；失败时不留下仅内存生效的更新。连接名固定，避免破坏现有路径引用。
4. “保存”只更新持久配置；当前主会话保持到下一次显式重连或自然失效。新建的后台独立会话读取最新配置，已经启动的会话继续使用其建立时的配置。“保存并重连”先保存，再使用新配置建立新主会话，成功后替换旧会话；失败时保留新配置及旧会话，并显示重连失败。界面明确提示保存与当前会话的关系。
5. 不复用 `ftp_disconnect` 完成重连，因为它会删除已保存配置。重连逻辑应使用不删除配置的会话替换路径。
6. FTP 目录读取和连接检查只在取得配置或替换会话时短暂持有管理器锁；网络请求在锁外执行，避免离线服务器阻塞编辑保存。

## Risks / Trade-offs

- [保存后主会话与新后台任务可能暂时连接不同服务器] → 在弹窗文案中说明，并提供“保存并重连”；对运行中任务不强行中断。
- [保存时写盘失败导致内存与磁盘不一致] → 先验证、持久化候选配置，再提交内存更新；测试失败路径。
- [已有密码明文仍存于本地 JSON] → 本变更不扩大其前端暴露面；安全存储迁移另行规划。

## Migration Plan

沿用现有 `ftp-connections.json` 格式，无数据迁移。回退应用版本后，已保存的字段仍可被旧版读取。

## Open Questions

无阻塞问题；后续可单独设计站点重命名和安全凭据存储。

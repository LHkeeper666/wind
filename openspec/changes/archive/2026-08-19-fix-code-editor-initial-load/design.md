## Context

`PreviewEditor` 在代码文件间切换时会先清空 `content`，随后异步读取文件。与此同时，编辑器模式的 `$effect` 会根据新 `filePath` 在下一帧调用 `initEditor()`。该回调没有关联本次 `loadGeneration`，因此可能在读取结束前以空字符串创建 CodeMirror；读取完成后 `mode` 未变化，编辑器不会再次初始化。

该问题依赖前端帧调度、Tauri command 往返时间和构建优化后的运行时序，不能依赖开发模式未复现来判定正确性。

## Goals / Non-Goals

**Goals:**

- 仅在当前文件加载成功且内容已就绪后创建或激活对应的 CodeMirror 会话。
- 使延迟的动画帧、文件读取和 tab 切换回调都不能覆盖较新的加载结果。
- 支持内容为空的有效文本文件。
- 保持现有 per-tab 会话、Vim 模式和焦点恢复行为。

**Non-Goals:**

- 不修改 Rust 文件读取与编码探测逻辑。
- 不改变 markdown、JSON、图片或其他 PreviewRouter 路径。
- 不改变 Python 补全能力或引入新的依赖。

## Decisions

### 将“内容就绪”作为编辑器创建前置条件

在 `loadFile` 中为当前加载保存路径和 generation，并在文本读取成功后再进入编辑器初始化流程。编辑器初始化必须使用经校验的本次内容快照，而不是从未标识状态的全局 `content` 推断。

不以 `content.length > 0` 判断就绪：空文件是合法的代码文件，必须能显示为空编辑器。

### 让异步 UI 回调失效化

保留为 DOM 可见性而使用的 `requestAnimationFrame`，但回调必须同时校验目标 tab、路径、加载 generation 和内容就绪状态。任一项不匹配时直接退出，不创建或替换会话。

仅校验路径不足以解决问题：同一路径可以被重新加载，旧回调仍可能使用旧的空内容。

### 保留已匹配的 per-tab 会话

只有目标 tab 已持有同一路径、且其内容属于当前有效加载时才激活会话；否则在内容就绪后创建新会话。不会复用属于旧文件或旧加载代次的会话。

相较于通过固定延时等待读取完成，该方案不依赖机器性能和打包/开发模式的调度差异。

## Risks / Trade-offs

- [加载状态与 tab 切换交错] → 所有异步边界统一使用 generation 和目标 tab/path 校验。
- [空文件被误判为未加载] → 使用显式就绪状态，不使用字符串长度。
- [焦点恢复时序改变] → 会话创建后继续沿用现有的 `requestAnimationFrame` 测量与 `focusActiveEditor` 路径。
- [重复初始化] → 创建前检查当前 tab 的会话标识；过期回调不产生副作用。

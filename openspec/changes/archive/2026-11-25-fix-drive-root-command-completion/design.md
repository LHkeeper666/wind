## Context

`CommandPalette.svelte` 将 `/` 转成 `\` 后，按最后一个分隔符拆分待补全路径。`/d` 因此从虚拟根目录 `\` 搜索；后端在该目录返回的盘符条目名称和路径均为 `D:\`。前端按普通子目录规则拼接 `\` 与 `D:\`，产生 `\D:\`。`resolvePath` 只识别 `\d`、`\d\...` 等盘符简写，不识别这个拼接结果。

## Goals / Non-Goals

**Goals:**
- 将虚拟根目录中的盘符匹配项补全为规范的绝对路径，如 `D:\`，供 `cd` 和 `e` 执行。
- 保持普通相对路径、绝对路径以及连续 Tab 循环的现有语义。
- 盘符根目录补全后，继续输入子路径或按 Tab 时能从该盘根目录补全。

**Non-Goals:**
- 改动后端虚拟根目录返回格式或 FTP 路径规则。
- 为命令面板新增其他路径语法。

## Decisions

1. 虚拟根目录的盘符候选使用后端返回的 `path` 作为补全结果，普通候选仍以目录前缀加 `name` 拼接。`path` 已是可执行的 `D:\`，无需再次拼接根前缀。候选须确认为本地盘符路径，避免将虚拟根目录中的 FTP 项错误当作盘符。
2. 补全时保留“输入以分隔符结尾”的信息。对 `D:\` 这样的根目录，Tab 应读取 `D:\` 并以空前缀搜索其子项；不能先去掉尾部分隔符再把 `D:` 当作当前目录中的名称。非根目录尾部分隔符也沿用进入该目录继续补全的直觉行为。
3. 补全结果与 `resolvePath` 使用一致的本地盘符表示：输入可接受 `/d`、`\d`，输出采用 `D:\`。不改动命令执行时已有的相对路径解析。
4. 拆分 `D:\co` 时得到的父目录 `D:` 须先还原为 `D:\` 再读取。`resolvePath` 当前不会把单独的 `D:` 识别为绝对路径；对补全分支作此处理即可，不改变命令执行的路径语义。
5. 记录补全前的路径输入与上一次生成的完整命令。若下一次 Tab 的命令仍等于上次结果且有多个候选，则沿用原输入和候选列表切换索引。用户输入其他键后清除循环状态；单一目录候选则允许下一次 Tab 进入该目录补全。

## Risks / Trade-offs

- [虚拟根目录还包含 FTP 项] → 盘符专用拼接规则只用于符合本地盘符根路径格式的候选；其他候选保持现有行为。
- [尾部分隔符改变候选查询范围] → 用盘符根目录、普通目录、连续 Tab 和无匹配场景验证查询目录与结果。

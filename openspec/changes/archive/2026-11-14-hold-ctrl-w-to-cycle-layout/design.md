## Context

全局 `keydown` 处理器用 `waitingForWindowKey` 表示 `Ctrl+W` 前缀，并在下一次按键时立即清除。`keyup` 目前只处理 Alt 切换器，因此无法识别 `Ctrl` 与 `W` 是否仍被按住。布局比例循环由 `layout.cycleLayout()` 独立完成，无需改动比例算法。

## Goals / Non-Goals

**Goals:**
- 用户按住 `Ctrl+W` 并逐次按 `m` 时，每次有效按键切换一次布局。
- 用户按住 `Ctrl+W` 并逐次按 `h/j/k/l` 时，每次有效按键执行现有焦点导航。
- 松开任一组合键后终止连续模式，同时保留现有短暂前缀输入方式。
- 状态栏前缀与实际可用快捷键状态一致。

**Non-Goals:**
- 改变布局循环顺序、比例或现有 `Ctrl+W h/j/k/l` 的导航目标。
- 提供用户可配置的快捷键或超时时长。

## Decisions

1. 在全局键盘处理模块中跟踪 `Ctrl` 和 `W` 的持续按下状态。按下 `Ctrl+W` 后，保留现有前缀超时以支持松键后输入；只要两键仍按住，连续 `m` 不清除前缀，且不受一秒前缀超时限制。松开 `Ctrl` 或 `W` 时结束连续状态。相较于每次 `m` 后重新设置一秒超时，这能准确表达“按住”的交互。
2. 仅在 `m/h/j/k/l` 的非重复 `keydown` 上执行一次既有操作。持续按住子键的自动重复事件由 `event.repeat` 识别并吞掉；松开再按才执行下一步。
3. 执行 `m/h/j/k/l` 后，只要 `Ctrl` 和 `W` 仍按住就保留前缀状态，允许混合输入这些子键。`h/j/k/l` 继续使用现有面板、终端及大纲焦点路由；没有可移动目标时保持原有结果。
4. 在窗口失焦和组件拆卸时清理按键状态及定时器，防止丢失 `keyup` 后残留的连续模式。

## Risks / Trade-offs

- [窗口失焦可能丢失松键事件] → 在现有窗口失焦入口清理持续状态。
- [按键自动重复可能连续跳过布局或焦点] → 只处理非重复的子键按下事件。
- [不同焦点目标可能提前消费按键] → 保持现有捕获阶段全局处理及 PDF 特例，并验证目录、预览和终端焦点。

## Context

Markdown 使用 markdown-it 生成链接，RST 解析器也生成 `<a href>`；预览 DOM 未统一拦截点击。预览内容由 PreviewRouter 异步替换，预览槽由 PanelLayout 管理，Tauri opener 已启用。现有 `handleActivate` 和 `handleActivateNew` 分别覆盖当前槽替换、已有槽复用及新槽创建。

## Goals / Non-Goals

**Goals:**
- 使 Markdown/RST 链接点击始终留在应用界面内完成文件或锚点导航，或者明确交给系统浏览器。
- 复用现有槽位状态、焦点和未保存修改保护。
- 统一处理渲染后动态替换的链接，不因重新渲染丢失行为。

**Non-Goals:**
- 在预览槽中嵌入任意网站或实现浏览器历史、下载等网页浏览能力。
- 改变图片资源加载方式或目录面板的打开行为。

## Decisions

### 在预览内容的稳定容器上委托点击

由 PreviewPane 或 PreviewEditor 的稳定容器识别来自当前 Markdown/RST 预览的最近 `<a href>`，在默认导航前调用 `preventDefault()`，再向 PanelLayout 传递打开文件意图及 Ctrl 修饰键。这样适配 PreviewRouter 的异步 DOM 替换。处理前核对当前文件/槽身份，避免旧内容触发错误操作。对 HTML 原生链接也采用相同行为。

### 先分类链接，再解析本地路径

`#fragment` 定位当前文档；`http:`/`https:` 通过 Tauri opener 的 `openUrl` 交给系统默认浏览器；相对路径、Windows 绝对路径及 `file:` URL 解析成规范本地路径。相对路径以被点击文档的所在目录为基准，先解码 URL 编码并分离 `?`/`#`，再确认目标存在且是文件。未知或危险协议不导航，显示反馈。解析与验证应复用项目现有文件系统能力，避免直接把 href 当作 WebView URL。`mailto:` 等非 HTTP(S) 协议不在本次打开范围内，保持应用页面稳定并提示不支持。

### 复用现有槽位打开入口

普通点击走当前槽打开入口，保留未保存修改确认；Ctrl + 点击走新槽入口，若目标已在当前工作区的其他槽打开则切换至该槽。若目标就是当前槽文件，不创建重复槽。打开时保持预览面板焦点，其他槽状态不变。

### 锚点在当前预览 DOM 中定位

查找当前预览内容中对应 `id` 的元素并滚动到可见区域；空锚点回到文档顶部。不存在的锚点显示轻量反馈，不触发 WebView 导航。Ctrl 修饰键不改变同文档锚点行为。

## Risks / Trade-offs

- [Markdown 允许原生 HTML，href 可能包含不受支持的协议] → 严格按允许的类别分派；所有预览链接先阻止默认导航。
- [Windows 路径、空格、编码及 `#` 语义复杂] → 为相对路径、绝对路径、`file:` URL、编码字符和锚点分别设置验证场景；不把无法确认的目标当文件打开。
- [文件替换期间存在异步渲染] → 在点击时读取并校验当前预览身份，使用稳定容器的事件委托。
- [一些网站无法嵌入] → 本次统一外部浏览器打开，不依赖 iframe。

## Migration Plan

仅改变预览链接点击行为，无数据迁移。通过撤销此变更的代码即可回退；既有工作区和预览槽数据结构保持不变。

## Open Questions

无阻塞项。目录链接、其他 URL 协议和跨文档锚点的更细交互可在实施时依据现有文件预览能力处理，超出本次明确支持的目标时给出反馈。

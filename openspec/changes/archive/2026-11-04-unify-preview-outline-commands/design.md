## Context

`CommandPalette.svelte` 目前将 `:toc` 直接转发给 `PreviewEditor.togglePdfToc()`，所以 Markdown 标题大纲不会响应。`PreviewEditor` 已有按文件类型分派的 `toggleOutline()`，Markdown 和 PDF 分别由各自状态对象管理。`:数字` 已转成零基页码传入 PDF 面板，但无适用类型及页码范围提示。

## Goals / Non-Goals

**Goals:**
- 统一主预览的目录命令，优先补齐 Markdown 的 `:toc`。
- 提供幂等的显式开关和易发现的 PDF 页码跳转命令。
- 无效操作明确反馈，保留现有快捷命令。

**Non-Goals:**
- 不改目录树的渲染和键盘导航。
- 不覆盖选择预览浮层或全屏 PDF 查看器。
- 不新增 Rust/Tauri 接口。

## Decisions

1. 命令面板通过 `PreviewEditor` 的统一大纲接口读取适用性与可见状态，并执行 toggle/open/close。这样命令语义与标题栏的目录按钮一致；不在命令面板分别维护 PDF/Markdown 状态。备选方案是直接在命令面板判断扩展名并调用两个状态对象，但会重复预览组件的路由逻辑。
2. `:toc` 保留切换语义；`:toc open`、`:toc close` 设为幂等操作。当前文件没有目录时提示，不假装成功。打开或关闭后焦点回到主预览内容，避免命令关闭后焦点被隐藏的目录占用。目录内部现有交互不变。
3. `:page N` 和 `:N` 走同一校验路径：仅当前主预览是已加载 PDF 且 `N` 为 1 到总页数的整数时，换算为零基页码并跳转。无效输入给提示；`N` 等于当前页仍可执行。备选方案是让底层 `scrollToPage` 静默拒绝，但用户无法区分输入错误与加载问题。
4. 在命令帮助中说明语法，并为命令解析与类型/边界行为补充针对性验证。

## Risks / Trade-offs

- [PDF 大纲异步加载] → 命令在目录数据尚未可用时给出“暂无目录”提示，不提前假定目录存在。
- [关闭目录时焦点仍在侧边栏] → 显式将焦点恢复到预览内容；验证 Markdown 和 PDF 两条路径。
- [保留 `:N` 与其他数字命令的潜在冲突] → 继续把纯正整数保留给 PDF 页码，非 PDF 环境显示适用性提示。

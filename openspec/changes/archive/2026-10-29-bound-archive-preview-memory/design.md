## Context

`PreviewEditor` 和 `SelectionPreviewOverlay` 均通过 `loadArchiveFile` 调用 `read_archive_file`。该命令返回完整 `Vec<u8>`；RAR 路径的 `header.read()` 在读出条目后才返回，前端又从 IPC 的 `number[]` 创建一份 `Uint8Array`。2026-10-28 的崩溃前，同一约 786 MiB 视频被反复请求，Windows 报告 `0xe0000008` 内存耗尽。当前前端的 generation 检查发生在 `invoke` 完成后，不能阻止已经启动的后端读取。

已有 `archive-browsing` 规格要求超过 10 MB 仅读取前 1 MB，但各格式的现有读取 API 不能保证在解压前有界地产生前缀。本变更将该行为改为明确的大小上限和占位提示。归档解压任务已有独立进程；条目预览仍在主进程，必须在分配前阻断超大内容。

## Goals / Non-Goals

**Goals:**

- 所有归档格式的预览读取在分配条目内容前执行同一个 10 MiB 上限，并由后端最终约束。
- 视频条目仅显示类型、大小和提取后打开的指引，不请求完整内容；其他超限条目显示可理解的占位提示。
- 普通预览与选中预览使用相同的限制和过期结果保护。
- 快速移动选中项时抑制尚未发出的旧请求，避免同一条目因响应式重复触发而反复读取。

**Non-Goals:**

- 实现归档内视频流播放、转码或缩略图生成。
- 改变完整归档解压、保存编辑内容和归档目录导航的行为。
- 以总物理内存或当前可用内存动态调整上限。

## Decisions

### 1. 后端在读取目标条目前检查解压后大小

归档预览命令设置固定的 `10 * 1024 * 1024` 字节上限。各格式读取目标条目时取得其声明的解压后大小，在 `Vec` 分配、解压和 IPC 序列化前拒绝超限条目。对缺失或不可信的长度，读取过程仍必须控制实际输出上限；不能只相信归档元数据。前端可用目录项大小提前显示占位，但后端检查仍是最终边界。

对于目前不能在读取过程中保证有界输出的格式，先拒绝大小未知的目标条目预览；需要时再单独设计流式读取。这样不会因“只展示前 1 MB”而在后台完整解压数百 MB。

`unrar` 0.5.8 的 `header.read()` 在库内部无上限地扩展 `Vec`，即使 RAR 头声明小于 10 MiB 也无法安全限制实际输出。因此 RAR 条目内容预览统一返回占位；目录浏览和完整提取路径继续可用。恢复小 RAR 条目预览需要另行实现有界的底层读取。
RAR 数据加密条目在未提供密码时仍提示输入密码；仅凭头部无法验证已提供密码是否正确，因此内容预览不执行该验证，完整提取时仍会验证。

备选方案是仅在前端根据列表的 `size` 跳过超大条目。其他调用方仍能直接触发命令，且目录元数据可能缺失，所以不够安全。

### 2. 将预览响应分成内容与占位两种结果

归档预览 API 返回结构化结果：成功时包含受限的字节和条目大小；超限或大小未知时返回不含字节的占位状态及原因。权限、密码错误、损坏归档和 `ARCHIVE_BUSY` 仍按现有错误路径传播。前端 `loadArchiveFile` 将占位状态转为可显示的预览结果，两个预览入口复用该逻辑。

视频扩展名在前端发起内容请求前直接走占位预览，并显示“提取后使用系统播放器打开”；后端限制覆盖绕过该前端判断的请求。对低于上限的图片和文本保留现有预览行为。

备选方案是把超限情况作为普通错误抛出。这样会落入通用读取失败界面，也不便区分文件过大与归档损坏。

### 3. 请求发出前检查目标身份

在调用归档内容命令之前，预览入口对短时间内的选择变化做合并，并再次检查 workspace、归档路径、条目路径与 generation。相同目标的重复触发共享或跳过在途请求；过期响应仍须在落地前检查 generation。Tauri `invoke` 尚不能直接取消已发出的原生命令，因此已开始的小文件读取只忽略结果；后端上限保证其成本有限。

备选方案是只保留现有的响应后 generation 检查。它能避免旧内容覆盖新内容，但无法阻止崩溃日志中所见的重复读取。

## Risks / Trade-offs

- [现有“大文件前缀预览”能力收缩] → 规格明确超限占位；未来确需前缀时，为各格式设计严格有界的流式实现。
- [归档声明大小与实际输出不一致] → 后端同时约束实际输出；针对异常大小和恰好位于阈值两侧的条目测试。
- [结构化结果影响调用方] → 搜索并更新 `read_archive_file` 的所有使用处，包括 `archive-browser.ts` 的导出包装及选中预览层。
- [防抖导致键盘预览延迟] → 使用短延迟，仅延后内容读取；目录选中和占位提示立即更新。
- [与其他进行中的预览变更相邻] → 实现时保留 tab 缓存、焦点和预览槽的现有身份守卫，不修改相关状态语义。

## Migration Plan

无持久数据迁移。先实现后端上限及响应，再接入两个前端入口与请求合并，最后运行 Rust、Svelte 检查和针对大归档的回归验证。若需要回退，按变更整体回退；不得只撤销后端上限而保留前端占位逻辑。

## Open Questions

无阻塞问题。实现时需核对各归档库对大小未知条目的读取接口；无法保证有界输出时按占位处理。

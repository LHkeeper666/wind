## MODIFIED Requirements

### Requirement: Insert 模式 Markdown 列表缩进按列表树移动

当 Vim 编辑器处于 insert 模式且 `Tab` 或 `Shift+Tab` 用于选中的 Markdown 列表项时，系统 SHALL 将每个选中的根列表项及其嵌套后代视为一棵列表树，移动根项一个列表层级并保持内部子结构。系统 SHALL 在标题、正文等列表边界处结束列表树，不得把后续独立列表作为前一列表的后代。

#### Scenario: 选中父项时子项一起缩进

- **WHEN** 编辑器处于 insert 模式，选区包含一个有嵌套子项的有序列表项，且没有补全建议被确认
- **AND** 用户按下 `Tab`
- **THEN** 选中的父列表项缩进一个列表层级
- **AND** 其嵌套子项仍保留在该父项下并保持相对层级
- **AND** 子项不会因为其行也在选区内而被重复缩进

#### Scenario: 混合层级选区只移动选中根项

- **WHEN** 编辑器处于 insert 模式，选区跨越不同嵌套层级的 Markdown 列表项，部分选中项是其他选中项的后代，且没有补全建议被确认
- **AND** 用户按下 `Tab`
- **THEN** 只有选中的根列表项被移动一个列表层级
- **AND** 后代列表项只作为其根项列表树的一部分移动
- **AND** 每棵被移动列表树的内部相对结构保持不变

#### Scenario: 选中的列表树反向缩进一层

- **WHEN** 编辑器处于 insert 模式，选区包含一个有后代的嵌套 Markdown 列表项
- **AND** 用户按下 `Shift+Tab`
- **THEN** 选中的列表项反向缩进一个列表层级
- **AND** 其后代仍保留在该项下并保持相对层级
- **AND** 选中的后代项不会被重复反向缩进

#### Scenario: 顶层列表项不会反向缩进出文档边界

- **WHEN** 编辑器处于 insert 模式，选中的 Markdown 列表项已经处于顶层列表层级
- **AND** 用户按下 `Shift+Tab`
- **THEN** 该项仍保持为顶层 Markdown 列表项
- **AND** 列表 marker 不会因为列表树反向缩进而被删除

#### Scenario: 独立列表不属于前一列表树

- **WHEN** 两个列表之间有标题或正文块
- **AND** 用户在前一个列表项按下 `Tab` 或 `Shift+Tab`
- **THEN** 后一个列表的项目不会跟随前一个列表树移动

### Requirement: Insert 模式 Markdown 有序列表缩进按容器重编号

当 Markdown 有序列表项通过 insert 模式 `Tab` 或 `Shift+Tab` 移动时，系统 SHALL 按列表项在所属有序列表容器中的兄弟位置，对每个受影响的有序列表容器重新编号。容器 SHALL 以实际列表分区、父项和层级为界；独立列表的编号 SHALL 互不影响。

#### Scenario: 有序列表项缩进到新的子容器时从 1 开始

- **WHEN** 编辑器处于 insert 模式，一个有序列表项被选中，且目标位置尚无有序子列表容器
- **AND** 用户按下 `Tab`
- **THEN** 被移动项在新的有序子列表容器中编号为 `1.`
- **AND** 原有序列表容器中的后续兄弟项连续重编号

#### Scenario: 有序列表项缩进到已有子容器时延续编号

- **WHEN** 编辑器处于 insert 模式，一个有序列表项被选中，且目标位置已有有序子列表容器
- **AND** 用户按下 `Tab`
- **THEN** 被移动项按其在该子有序列表容器中的位置编号
- **AND** 该子有序列表容器中的所有兄弟项连续重编号
- **AND** 原有序列表容器中的后续兄弟项连续重编号

#### Scenario: 有序列表项反向缩进后重编号源容器和目标容器

- **WHEN** 编辑器处于 insert 模式，一个嵌套有序列表项被选中
- **AND** 用户按下 `Shift+Tab`
- **THEN** 被移动项按其在父有序列表容器中的新位置编号
- **AND** 原嵌套有序列表容器中剩余的兄弟项连续重编号
- **AND** 父有序列表容器中的后续兄弟项连续重编号

#### Scenario: 混合层级有序列表选区按容器独立重编号

- **WHEN** 编辑器处于 insert 模式，选区跨越多个嵌套层级的有序列表项
- **AND** 用户按下 `Tab` 或 `Shift+Tab`
- **THEN** 每个受影响的有序列表容器都从其第一个可见兄弟项开始独立重编号
- **AND** 一个有序列表容器中的编号不会复用另一个容器的全局计数

#### Scenario: 标题或正文分隔的顶层列表独立编号

- **WHEN** 文档中有两个由标题或正文块隔开的顶层有序列表
- **AND** 用户在其中一个列表按下 `Tab` 或 `Shift+Tab`
- **THEN** 系统仅更新受影响列表的源容器与目标容器
- **AND** 另一个列表的 marker 保持原样

#### Scenario: 单独空行不切断连续列表

- **WHEN** 同一有序列表的两个项目之间只有空行
- **AND** 用户通过 `Tab` 或 `Shift+Tab` 改变其中一个项目的层级
- **THEN** 系统根据同一列表内的实际兄弟关系连续编号

#### Scenario: 同级列表类型切换产生独立容器

- **WHEN** 有序列表与无序列表在同一层级相邻
- **AND** 用户移动其中一个有序列表项
- **THEN** 系统不会跨越无序列表延续有序编号

#### Scenario: 围栏代码块中的数字行不参与编号

- **WHEN** 围栏代码块中存在形似 `1. item` 的行
- **AND** 用户在代码块之外移动有序列表项
- **THEN** 代码块中的行保持原样且不作为列表项目参与编号

## ADDED Requirements

### Requirement: Markdown 有序列表 Enter 仅更新所属分区

当 insert 模式的 `Enter` 延续或结束有序列表项时，系统 SHALL 只调整该项所属列表容器及受其结构变化影响的容器，不得修改其他独立列表的 marker。

#### Scenario: 后一章节延续列表

- **WHEN** 两个顶层有序列表之间有 Markdown 标题，且后一个列表以 `1. item` 开始
- **AND** 用户在后一个列表末项按下 `Enter`
- **THEN** 新项目按后一个列表的顺序递增
- **AND** 两个列表之间不连续编号，前一个列表的 marker 保持原样

#### Scenario: 删除空列表项不影响其他分区

- **WHEN** 用户在有序列表的空项目上按下 `Enter` 以退出列表
- **THEN** 系统只重新编号该列表中受影响的项目
- **AND** 其他独立列表的 marker 保持原样

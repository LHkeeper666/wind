## Context

`editor-text-keys.ts` 以正则识别列表项，并用 `parentLineIndex:indentColumns` 作为编号容器键。顶层项目共用 `root:0`；`hasOrderedContainerBarrier` 在顶层无法把标题或正文判为边界。列表树扫描也只按缩进弹出父项，跨过非列表块时可能保留过期父项。Enter、Tab、Shift+Tab 都会运行全文件编号。

现有编辑交互允许通过 Tab 将列表 marker 缩进四列；Markdown 渲染解析器可能将孤立的四列缩进行解释为代码块。因此不能直接用渲染器的列表 token 全面替换编辑器现有的树模型。

## Goals / Non-Goals

**Goals:**

- 在编辑器现有列表树模型中识别独立列表分区，并使父子关系和编号使用同一分区信息。
- 保持同一列表中的空行、续行和嵌套项；在标题、正文块及同级列表类型切换处断开分区。
- Enter、Tab、Shift+Tab 只改动受编辑影响的列表容器；其他列表的原始编号保持不变。

**Non-Goals:**

- 不重做 Markdown 渲染或替换 Vim/CodeMirror 的缩进操作。
- 不把所有 Markdown 语法的解析与渲染完全统一。
- 不在本变更中实现 Vim 普通/可视模式缩进后的编号接入；该接入由现有独立 change 负责。

## Decisions

### 在现有行扫描中加入结构边界和分区 ID

扫描行时跟踪列表层级、空行及围栏代码块状态。标题、普通正文块、分隔线等结束其所在层级的列表；无空行的普通文本只有在可作为当前列表项续行时才留在原分区。单独空行不构成边界，后续列表项是否延续由下一条有效内容决定。同级 ordered/unordered 类型切换产生新分区。围栏代码块中的 marker 不作为列表项。

给每个独立列表分区稳定的扫描内 ID；嵌套列表另有子分区并记录实际父项。跨边界时清除失效的父项栈。保留现有 marker 正则和四列缩进编辑行为。相比直接使用 `markdown-it` token，此法可兼容编辑中的临时缩进形态，同时修正当前边界缺陷。

### 用分区与父项共同标识编号容器

有序项目只与同一分区、同一父项和同一缩进层级的兄弟项目连续编号。新容器沿用现有从 `1.` 开始的自动编号规则；未受编辑影响的容器即使含有手动起始数字，也不改写。列表树的 subtree 结束位置不得越过分区边界。

### 按编辑影响范围选择容器

Enter 选择光标所在容器；Tab/Shift+Tab 选择移动前后的源容器、目标容器及其受影响的嵌套容器。构建编辑后的列表结构后，只对这些容器产生编号变更。若一次选区跨越多个独立列表，分别处理每个分区。复用同一编号入口供后续 Vim 普通模式缩进变更调用。

## Risks / Trade-offs

- [Risk] 逐行扫描未覆盖所有 CommonMark 边界，尤其是复杂引用块或 HTML 块。→ 先覆盖当前编辑器支持的列表形态和明确的块边界；为不识别的结构增加回归样例，必要时再引入解析器辅助判断。
- [Risk] 编号变化会改变 marker 宽度，影响缩进列和后续父子判断。→ 在移动完成后重新扫描结构，再生成编号差异；测试 `9.` 到 `10.` 的情况。
- [Risk] 精确筛选影响容器可能遗漏源/目标邻居。→ 根据移动前后结构分别收集容器，并测试缩进、反向缩进及跨分区选区。

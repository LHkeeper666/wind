## Context

三栏 PDF 预览使用 `PdfPreviewPanel.svelte` 计算可见瓦片，`PdfRenderScheduler` 串行调用后端 PDFium。视口可见瓦片集合改变会递增 generation 并清空旧队列；预取范围固定，初次低清批量呈现后没有逐页完整底图保障。目标样本为 171 页、页面约 1560×540 的双语 PDF，连续 `j/k` 容易快速跨页。

## Goals / Non-Goals

**Goals:** 连续滚动时优先显示完整低清页面，再以高清瓦片覆盖；减少滚动导致的重复渲染；维持有界内存和单路 PDFium 渲染。

**Non-Goals:** 更改全屏查看器、PDF 文本与链接行为、后端 PDFium 并发模型，或承诺任意滚动速度下绝无首次进入视口的延迟。

## Decisions

### 1. 每页独立的低清底图

以现有页面渲染命令生成受最大像素数约束的低清整页图，按文件修订、页码和适用缩放档位缓存。底图覆盖整个页面，高清瓦片置于其上。底图与瓦片都完成解码后才进入 DOM；仅当页面范围被高清覆盖时移除该页底图，或由缓存预算淘汰非可见底图。较大的页面须进一步降低底图比例以维持像素预算。相比将低清瓦片逐块显示，整页底图可避免用户看到块状加载边界。

### 2. 以可复用工作项调度渲染

任务键包含文件修订、页码、比例和区域，不再把滚动 viewport generation 当作结果有效性的唯一条件。每次滚动重新计算任务优先级并清除预取窗口以外尚未开始的任务；窗口内已排队与正在执行的任务保持复用。完成结果在文件修订与比例仍有效时进入缓存，只有仍需要该结果的已挂载页面可显示它。文件变化、tab 释放或缩放档位变化时清除不兼容任务。维持一次只派发一个 PDFium 渲染请求。相比简单增加并发，此方案避免后端锁争用与无效工作。

### 3. 方向和速度驱动的有界预取

从相邻滚动采样计算方向与速度，优先级依次为可见缺失底图、前方底图、可见高清、前方高清、后方缓存补充。预取窗口基于视口高度，静止时覆盖相邻页面；连续滚动时向前扩展，设置最大页面数、任务数与缓存预算。反向时重新排序，保留仍在窗口内的结果。面板拖动尺寸期间沿用既有暂停预取规则。

### 4. 保留可见画面直到替代画面就绪

高清瓦片先完成解码再显示。缩放和尺寸变化期间保留可用的旧画面，稳定后重建请求；不兼容结果不可贴到当前画面。底图及高清缓存使用像素字节成本核算，优先淘汰远离视口的非固定内容；可见底图在其高清覆盖完成前固定。

## Risks / Trade-offs

- [整页底图仍有渲染成本] → 限制底图最大像素数，优先前方最近页面，并用目标 PDF 测量首次跨页延迟。
- [缓存预算不足导致反复淘汰] → 将可见底图计入现有总预算，限制前方预取页面数并观察淘汰率。
- [旧结果误贴到新文件或比例] → 将文件修订和渲染比例放入任务键，显示前检查页面挂载状态与会话身份。
- [快速跳转仍可能先看到占位] → 将验收重点限定为正常连续 `j/k` 滚动；跳转另行沿用现有加载反馈。

## Migration Plan

仅调整运行时预览逻辑与规范，无持久数据迁移。先实现底图和任务复用，再加入速度预取与预算调优；若性能回退，可恢复旧调度路径。

## Open Questions

底图最大像素数与预取页面上限需在目标 PDF 和常见高页 PDF 上实测后确定，不在规范中固定魔法数。

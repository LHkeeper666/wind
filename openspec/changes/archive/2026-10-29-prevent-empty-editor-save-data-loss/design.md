## Context

日志在 23:38:27 显示 `TODO.md` 缓存恢复为 6644 字符，紧接着同一显示目标的第二次恢复将前端内容清零；23:48 磁盘仍为 11994 字节，23:49:00 发生实际修改，23:49:07 磁盘已为 0 字节。日志没有写入路径和字节数，不能确定最后写入者。当前 `restoreTabContent` 无条件调用 `deactivateTab`，缓存允许暂态空内容覆盖有效快照，命中后仅凭修改时间决定是否重读；普通保存由多个前端入口直接调用 `write_file`，后端使用覆盖式 `fs::write`。

此变更合并实现 `prevent-tab-switch-empty-preview-cache` 的全部待办，并增加磁盘保存保护及可追溯日志。实施时需与正在进行的 `restore-workspace-context-on-switch` 代码协调，保留焦点、滚动和编辑器会话恢复行为。

## Goals / Non-Goals

**Goals:**

- 同一显示目标的预览提交不再破坏内容；不同目标仍在路径变更前同步清理旧显示。
- 只缓存成功读取或用户编辑的内容；异常空快照自愈，合法空文件和主动删空草稿不丢失。
- 对所有普通文本保存入口使用同一保护逻辑，拒绝来源不明的空写和已变更磁盘版本的覆盖，并给出明确反馈。
- 使保存成功、失败、拒绝可通过不含正文的日志还原。

**Non-Goals:**

- 确定 23:49:00 那次历史写入的进程；现有日志不含该信息。
- 阻止 Wind 之外的程序直接写入文件，或提供文件版本备份与恢复。
- 重构归档内写入、FTP 传输和其他文件操作。

## Decisions

### 1. 以显示身份决定是否执行过渡清理

显示身份由工作区 tab ID、预览槽 ID、规范化文件路径构成。`restoreTabContent` 仅在身份变化时于设置目标路径之前同步调用 `deactivateTab`；切换器确认已预览的同一身份时保持现有内容和编辑器会话，但仍执行正式激活的 MRU、布局、项目模式、焦点等收尾。异步回调继续校验身份与 generation。只比较路径会误合并两个独立 tab；完全跳过确认流程会遗漏收尾。

### 2. 文本状态与身份绑定，缓存仅接受有效快照

文本内容具有 `loading`、`ready`、`error`、`transition` 状态，并记录身份、读取所得原始大小及版本。成功读取零字节文件是 `ready`；用户的真实编辑操作包括删空也产生 `ready` 草稿与修改标记。`deactivateTab` 转为 `transition`，加载失败转为 `error`；这两种状态和 `loading` 不能用空字符串覆盖该身份的有效缓存。缓存命中时恢复该文件自己的大小和版本；无未保存修改的非空文件若遇到空内容且来源无效，立即丢弃并重读，不因修改时间相同而停留空白。已有未保存草稿优先，不自动重读覆盖。

编辑入口只依据状态提示：`loading` 等待、`error` 失败及重试、`ready` 可编辑，包括真实空文件。仅凭 `content === ''` 无法区分这些情况。

### 3. 统一普通文本保存与空写校验

`PreviewEditor` 的普通保存、切槽保存及 `FullscreenEditor` 若仍在使用，均走同一保存流程。保存请求携带目标路径、当前显示身份、内容、加载/编辑来源、读取时磁盘版本及入口标识。前端拒绝非 `ready`、身份不匹配或无真实编辑记录的异常空内容；用户明确在编辑器中删空后可以保存。后端在打开目标前再次检查空写前置条件与磁盘版本，避免仅依赖前端状态。非空磁盘目标遇到无有效编辑来源的空内容时拒绝覆盖。磁盘版本在加载后发生变化时拒绝保存并提示用户重新加载或处理冲突，不静默覆盖。

版本检查至少使用文件大小与高精度修改时间；不要沿用当前按秒取整的 `get_file_metadata.modified` 作为唯一依据。保存成功后返回新的版本给当前状态和缓存。Windows 上检查与写入之间仍有竞态，实施时应尽可能收紧窗口，并在测试中明确此边界。保存所有入口应给出可见的成功或拒绝结果，不能仅把错误写入日志。

### 4. 保存日志只记录可诊断元数据

在统一保存边界生成一次操作 ID，记录请求入口、规范化路径、原文件大小、待写 UTF-8 字节数、加载/编辑来源、版本检查结果及最终结果或拒绝原因。读取失败、缓存驱逐和重读也使用相同显示身份字段记录。日志不写文件正文、密钥或编辑文本。路径沿用现有文件操作日志的访问范围。用操作 ID 串联前后端记录，避免重复事件被误判为多次写入。

## Risks / Trade-offs

- [合法清空被误拒绝] → 以真实编辑产生的草稿来源和已加载原始版本判断；测试删空后 `:w`、`Ctrl+S` 与切槽保存。
- [空草稿被磁盘重读覆盖] → `isModified` 且来源为用户编辑时保留草稿。
- [旧缓存或旧异步响应污染新目标] → 同时校验 tab、槽、路径与 generation。
- [按秒修改时间漏掉快速外部修改] → 使用高精度版本加文件大小；测试同一秒内的修改。
- [元数据检查与覆盖之间的竞态] → 尽量在后端保存边界内检查并写入，文档明确不能约束外部进程并发写入。
- [两个进行中提案范围重叠] → 本变更作为完整实施清单；实施时不要分别执行旧提案的同项任务。

## Migration Plan

运行时缓存不跨进程持久化，无数据迁移。实施后先运行定向回归测试、`npx svelte-check` 和 `cargo check`，再手动验证切换与保存。若回退，旧版应用仍可读取文件；不要用回退操作覆盖用户数据。

## Context

项目树的自动刷新由文件系统事件触发，手动刷新由 `R` 触发。两条路径在重载节点后调用 `selectTreePathOrAncestor` 恢复选中路径。该函数默认向 `DirectoryPanel.selectByIndex` 发送即时选中通知，进而设置 `selectionPreview` 并显示覆盖编辑器的只读预览层。保存文件不应被视为用户主动选择目录项。

## Goals / Non-Goals

**Goals:**
- 刷新后保留有效的项目树选中路径，同时不因刷新打开选中预览层。
- 保留用户主动选择目录项时的预览行为。
- 编辑 Markdown 后执行 `:w`，编辑器继续可见并保持编辑状态。

**Non-Goals:**
- 改变 `:w`、`:q` 或 `:wq` 的 Vim 语义。
- 改变文件监听、刷新范围或预览渲染机制。

## Decisions

- 在 `refreshProjectTree` 和 `refreshProjectDirectories` 恢复选中路径时传入 `{ notify: 'silent' }`。现有 `SelectOptions` 已支持静默选择，无需新增状态或事件。与在保存流程中强制隐藏预览层相比，这从刷新通知源头修正问题，也覆盖其他文件变更和手动刷新。
- 保持 `selectTreePathOrAncestor` 默认即时通知。键盘和鼠标主动选择、展开/折叠后确实改变目标的路径仍按既有逻辑通知，避免影响用户预览行为。
- 已存在的选中预览层在后台刷新时保持原可见状态；静默恢复仅避免产生新的选择事件，不主动隐藏预览层。

## Risks / Trade-offs

- [刷新后原节点已消失，需要回退到祖先节点] → 静默更新树光标，但不自动打开祖先节点预览；用户下一次主动选择时再更新预览。验证此场景的选中路径与编辑器状态。
- [其他刷新入口仍发送即时选中通知] → 检查项目树相关刷新调用，并分别验证自动刷新与 `R` 手动刷新。

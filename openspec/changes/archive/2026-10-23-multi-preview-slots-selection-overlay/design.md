## Context

当前 `TabState` 只保存一个 `selectedFile`；`PanelLayout` 将目录选中直接传给唯一的 `PreviewEditor`。`PreviewEditor`、`PreviewPane`、`TextEditorHost` 和 PDF 会话按顶层 tab ID 缓存状态。目录选择已有 200 ms 防抖，文件与 PDF 加载仍可能异步完成。此次改动需要同时保留项目模式、归档与回收站预览、未保存修改保护和现有预览资源预算。

## Goals / Non-Goals

**Goals:**

- 每个工作区拥有独立的、有序预览位列表、当前位与独立选中预览层。
- 选中预览层只读，不改变预览位的文件、编辑会话或阅读位置。
- 用户明确控制预览位的新建、替换、切换与关闭；始终至少有一个位。
- 快速目录选择、工作区切换与异步渲染不出现旧内容覆盖或编辑状态丢失。

**Non-Goals:**

- 同时并排显示多个预览位、跨工作区移动预览位、会话跨应用重启持久化。
- 更改顶层工作区 tab、三栏布局或项目树目录快捷键的语义。

## Decisions

### 1. 预览层与预览位分别建模

工作区状态包含 `slots: PreviewSlot[]`、`activeSlotId`、`selectionPreview: { path, isDirectory, visible }`。预览位 ID 在工作区内稳定；所有缓存与异步任务使用复合身份 `(workspaceTabId, slotId)`，避免仅用顶层 tab ID 造成互相覆盖。预览层拥有独立身份与加载代次，不占预览位，也不参与编辑器缓存。目录选中只更新预览层；显式打开才更新预览位。相比继续复用 `selectedFile`，此模型把“查看选中项”与“打开文件”明确分开。

### 2. 预览层覆盖内容区域，标签栏保持可用

预览位标签栏由 `PanelLayout` 持有，替代预览面板顶部现有标题栏；当前位名称、修改标记、模式、布局与大纲控制均保留可见入口。预览层在标签栏下方覆盖内容，不卸载当前位的编辑 DOM；点击标签、`l`、`L`、新建空位或切换位收起预览层。预览层不抢夺目录键盘焦点；单纯焦点转移不改变显示层。可阅读与滚动目录、图片、PDF 及大纲，但不提供编辑或保存入口。

### 3. 明确槽位生命周期和打开语义

新工作区创建一个空预览位。选中项只显示在预览层。`l` 在当前位打开文件，`L` 新建位打开文件；新建空位和关闭位提供顶部按钮、命令及不冲突的快捷键。替换或关闭有未保存修改的位时，复用保存、放弃、取消流程；取消保持原位和预览层状态。关闭最后一个位表现为将其重置为空位。切换位恢复该位的编辑模式、光标、滚动、PDF 页码与大纲。允许同一路径出现在不同位，但必须共享一致的文件修改检测；初期可选择激活已有位以避免同时编辑冲突，具体行为由规范固定。

### 4. 复用只读渲染能力，不复用完整编辑器

从当前预览管线抽出只读文件加载/渲染入口供选中预览层使用，包括目录、文本、图片、PDF、归档与回收站适配；避免再实例化完整 `PreviewEditor`，因为它拥有写入、文件监听、编辑会话与顶层 tab 缓存。每次选中增加加载代次，只有最新 `(workspaceTabId, path, generation)` 可以提交结果。旧请求可取消则取消，不能取消时丢弃结果并释放资源。沿用目录选择的防抖，层内保留自己的滚动状态，不触碰当前位。选中预览层的重资源使用现有 PDF/视频预算，隐藏或工作区关闭时释放层专属资源。

### 5. 渐进调整现有缓存

先抽象预览位状态与缓存键，再连接多位 UI；不直接把现有 `PreviewPane` 的 per-tab DOM slot 当成新预览位，因为两者层级不同。切换位保存当前状态并恢复目标状态；只保留预算内的活动 DOM/重资源，其他位保留轻量快照并按需重建。工作区切换继续作为外层状态切换。

## Risks / Trade-offs

- [隐藏的编辑器被重建，丢失撤销历史或焦点] → 保持当前位挂载；切换位时显式保存/恢复会话，并验证撤销历史行为。
- [快速选中使旧异步结果覆盖新结果] → 独立 generation、路径与工作区身份检查，清理过期资源。
- [多个 PDF/图片位占用过多内存] → 延续现有资源预算，仅活动位和预算内缓存保留重画面。
- [同一文件在多个位中出现修改冲突] → 打开重复路径时激活已打开位；后续若需要双视图另行设计。
- [特殊上下文预览行为不一致] → 归档、回收站、项目树和普通目录逐一覆盖场景与验证。

## Migration Plan

先引入新状态并将旧单文件状态映射到首个预览位，再切换目录选中通路，最后接入多位 UI 与资源清理。开发期间每一阶段都运行 Svelte 类型检查，并针对状态转换与异步加载做验证。若回退，移除新预览层和多位状态接线即可恢复旧单预览路径；不涉及持久数据迁移。

## Open Questions

快捷键具体组合与命令名称需要在实现前核对现有映射，避免占用 `Ctrl+W h/j/k/l/m`。如无冲突，优先考虑 `Ctrl+W n` 新建、`Ctrl+W c` 关闭，并为位间切换选择独立组合。

## Context

`PreviewEditor` 保存后更新自身的 `isModified`，但 `PanelLayout` 标签栏还读取持久化的 `slot.isModified`，该值只在切槽等快照操作时更新。预览编辑器的 `VimOverlay` 与 CodeMirror 命令处理器都支持 `:wq`；前者不等待保存，后者虽等待 Promise，却没有检查保存是否成功。底层文本写入已经返回版本并报告错误，本变更沿用该机制。

外部文件修改通知在编辑模式下曾被跳过。预览重新加载后，CodeMirror 会话仍可能按预览槽与路径复用旧文档；撤销到旧保存基线也不代表草稿与当前磁盘一致。

## Goals / Non-Goals

**Goals:**

- 标签圆点始终对应预览位当前未保存草稿。
- 保存成功且草稿已干净后，`:wq` 才退出编辑模式；失败或保存期间产生新修改时保留编辑模式。
- 两条 Vim 命令路径采用相同的保存结果语义。
- 外部文件变化时刷新干净草稿的预览和编辑器会话；保留有未保存修改的草稿并提示冲突。

**Non-Goals:**

- 改动后端写入与版本冲突校验。
- 改动全屏编辑器或批量重命名的保存交互。

## Decisions

1. `PreviewEditor` 在修改状态变化及保存完成后，向 `PanelLayout` 报告带工作区 ID、预览位 ID 的修改状态；父组件仅更新匹配预览位。保存完成时按当前内容与已保存快照比较，避免清除保存期间新增修改。仅依赖切槽快照会继续留下旧圆点。
2. 预览编辑器保存入口向调用者返回可用于退出判断的结果。无修改时视为成功；写入失败或完成后仍有新修改时不可退出。`:w` 只触发保存，`:wq` 等待结果后决定是否退出。两条命令路径共享该语义，避免一个路径绕过检查。
3. 保存请求记录目标工作区、预览位和路径；异步完成后的状态更新只作用于原目标。目标切换时遵守现有身份校验，不把结果应用到当前其他预览位。
4. 监听通知、退出编辑、进入编辑和切回缓存槽时核对磁盘大小与高精度修改时间。干净草稿变化时同时失效预览缓存和 CodeMirror 会话，再读取磁盘；有未保存修改时保留草稿、提示外部变化，继续沿用后端保存冲突保护。无修改的 `:wq` 在退出前也执行版本核对。
5. 新建 CodeMirror 会话使用原始保存基线判断修改状态，不将恢复的草稿直接标记为已保存。

## Risks / Trade-offs

- [保存期间切槽] → 使用请求开始时的身份定位结果，并保留现有身份拒绝机制。
- [保存期间再次编辑] → 比较当前草稿和已保存快照；`:wq` 不退出，用户可再次保存。
- [已有两套命令处理] → 检查 overlay 和 CodeMirror handler 的 `:w`、`:wq`、`:x` 路径，避免只修复其中一种输入方式。
- [外部写入与本应用保存通知交错] → 本应用保存期间延后处理文件变动通知，完成保存后重新核对版本。

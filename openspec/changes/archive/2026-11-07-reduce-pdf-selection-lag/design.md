## Context

`DirectoryPanel` 的每次 j/k 移动立即调用 `onSelect`，`SelectionPreviewOverlay` 随路径变化启动 `get_pdf_info`。该命令在全局 PDF 缓存锁内加载文档并遍历全部页面尺寸。前端虽通过 generation 忽略过期响应，但不能撤销已发出的后端工作。`PdfPreviewPanel` 当前为每页挂载一个 `.page-slot`。

## Goals / Non-Goals

**Goals:** 目录高亮即时变化；快速经过 PDF 时仅对停留目标启动加载；过期工作不继续挂载或预取；长 PDF 的 DOM 节点量有界，同时保留正确滚动、页码和跳转。

**Non-Goals:** 改动已打开预览位的 PDF 加载语义、改变 PDFium 缓存容量、修改 Tauri 命令接口或重写 PDF 栅格渲染器。

## Decisions

1. 在选中预览层的 PDF 分支设置约 120 ms 的可取消等待。路径变化时立即清除旧内容并更新目标身份；等待结束后再次校验 workspace、路径、archive 和 generation，再调用 `get_pdf_info`。非 PDF 保持现有加载路径。等待应只影响预览内容，不阻塞目录高亮和后续按键。选择在预览层处理，而不是延迟 `tabs.selectEntry`，以遵守现有立即切换目标的规格。
2. 已发出的请求仍可能完成，继续用 generation 拒绝其结果；PDF 面板销毁或失活时撤销待执行瓦片并阻止后续预取。复用现有渲染调度器，不引入跨层全局队列。对同一目标的重复触发避免重新启动等待和相同信息请求。
3. 保留全部页面尺寸和累计偏移数据，但仅挂载可见页及少量缓冲页的 DOM。使用前后占位高度维持总滚动范围；页面查找、跳页、目录定位和文字层要基于累计偏移而非假设所有 `.page-slot` 都存在。窗口大小变化与缩放后重算可见窗口。
4. 先记录按键到高亮、PDF 信息请求与首屏显示的耗时，再用多 PDF 和长 PDF 场景验证改善。若后端锁依旧成为主要瓶颈，再另开变更讨论后端取消或排队机制。

## Risks / Trade-offs

- [单次选中预览出现约 120 ms 等待] → 仅应用于目录选中预览中的 PDF，保留加载中的空白遮罩，不延迟高亮或打开文件操作。
- [虚拟页窗口影响跳转和阅读位置] → 用累计偏移计算目标位置，覆盖大纲跳转、滚动、缩放与重新进入预览的回归验证。
- [已派发的 PDFium 调用不可取消] → 在派发前合并和校验；后端耗时仍需实测，避免把前端防过期误当作取消后端工作。

## Migration Plan

无数据迁移。按任务顺序先完成选中加载合并，再实现虚拟页面；每步运行前端类型检查及相关测试。若虚拟页面出现定位回归，可单独回退该部分，保留请求合并。

## Open Questions

120 ms 为初始值，实施时依据键盘连发与单次预览的实测调整。长 PDF 的缓冲窗口页数沿用现有可见区域加邻页策略。
